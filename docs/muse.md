# Museとの連携・注意事項

xangiに保存した依頼をMuseがMCP経由で取得し、処理結果を保存すると、xangiが元の会話へ通知する仕組みで運用しています。

## 処理の流れ

1. xangiが依頼を保存します。
2. Museが定期的に未処理の依頼を確認し、`get_job`で内容を取得します。
3. `queued`の依頼を`claim_job`で受領して処理し、`submit_result`で結果を保存します。
4. xangiが結果を元の会話へ通知します。保存済みの成果物は取得して添付します。

DotsのMCP Eventsによる新着通知とは異なり、Muse側のハートビートで依頼を取得しています。現在の運用は30分間隔で、登録直後に処理が始まるとは限りません。急ぐ場合はMuseに既存のジョブIDを伝えて取得を依頼します。

## 注意事項

- 定期取得はMuse側で設定しています。本拡張が巡回を自動設定するわけではありません。依頼の期限には取得待ちと処理時間を含めてください。
- `running`は受領済み、`completed`は結果保存済みを表します。進捗や元の会話への通知は別に確認し、取得待ちを理由に同じ依頼を重複登録しないでください。
- 現行の通知文とファイル取得ヘルパーは、接続先が`xangi-dots`固定です。別の登録名で運用する場合は、依頼を登録した接続を明示して結果・添付を取得する必要があります。
- Dots向けのファイル転送方式や容量上限が、そのままMuseで使えるとは限りません。保存済みファイルは取得後にサイズとSHA-256を照合してください。

APIの詳細は[API一覧](api.md)、結果・通知の状態は[使い方](usage.md)を参照してください。
